Pilih alat AI kamu

Alat AI adalah aplikasi yang menulis dan membetulkan kode atas perintahmu. Pilih satu, petunjuk di panduan ini ikut berubah. Tombol yang sama ada di kanan bawah.

Freebuff Desktop gratis, tanpa API key dan tanpa kartu kredit. Biayanya ditutup iklan teks.

OpenCode Desktop bersifat open source dan menyediakan model gratis bawaan. Model gratis bisa dibatasi atau berganti sewaktu-waktu.

Komputermu terdeteksi otomatis. Kalau salah, ganti Windows atau Mac di kanan bawah.

0.1Buat akun GitHub dan Vercel

GitHub

Daftar di github.com/signup, lalu verifikasi emailmu.

Vercel

Buka vercel.com/signup dan pilih Continue with GitHub.

Berhasil kalau

Kamu bisa membuka GitHub dalam keadaan login, dan dashboard Vercel terbuka.

0.2Pasang Git

Windows

Buka git-scm.com/install/windows, unduh pemasang 64-bit, lalu jalankan. Pertahankan pilihan bawaan, termasuk Git Credential Manager.

Mac

Buka git-scm.com/install/mac dan ikuti petunjuk di halaman itu.

Berhasil kalau

git --version menampilkan nomor versi. Login GitHub tidak diminta sekarang; jendela login muncul sendiri saat push pertama.

0.3Pasang editor dan alat AI

Editor

Pasang Visual Studio Code. Kamu akan sering melihat file yang diubah AI di sini.

Alat AI

Buka freebuff.com/desktop, unduh versi untuk komputermu, lalu pasang.

Alat AI

Buka opencode.ai/download, unduh aplikasi desktop, lalu pasang.

Berhasil kalau

Aplikasi alat AI terbuka dan menampilkan layar awal.

Kalau gagal

Peringatan keamanan saat membuka aplikasi? Lihat bagian Troubleshooting. Kalau tetap tidak jalan, ganti alat AI lewat tombol kanan bawah.

1

Aturan dan pengaman

Kamu merawat aplikasi orang lain: memperbaiki tampilan, membetulkan bug, dan menutup celah keamanan. Perananmu adalah pengambil keputusan dan pemeriksa, AI yang mengetik kodenya.

Commit kecil, sering

Satu perbaikan, satu commit. Kalau AI merusak sesuatu, kamu bisa kembali ke versi terakhir yang jalan.

Rahasia tidak masuk repo

.env.local berisi kunci sesi. File itu tidak boleh ikut ter-commit, dan repo publik berarti siapa pun bisa membacanya.

Klien tidak dipercaya

Validasi dan izin harus ada lagi di server. Memeriksa di browser saja bukan keamanan, hanya kenyamanan.

Satu tugas, satu prompt

Jangan minta AI mengerjakan revamp, fix, dan security sekaligus. Periksa hasil tiap langkah sebelum lanjut.

2

Buat akun GitHub dan repo baru

Sekitar 15 menit

Repo adalah "folder proyek di internet". Semua kode, riwayat perubahan, dan kolaborasi terjadi di sana. Kamu butuh satu repo milikmu sendiri untuk mengerjakan tugas.

2.1Buat akun GitHub

Langkah

Buka github.com/signup. Isi email, password, dan username. Username akan jadi bagian alamat profilmu: github.com/[username].

Verifikasi

Cek email, masukkan kode verifikasi yang dikirim GitHub. Tanpa verifikasi, kamu tidak bisa membuat repo.

Berhasil kalau

Kamu bisa login ke github.com dan melihat dashboard awal (halaman dengan daftar repo).

2.2Buat repo baru

Isi form

Nama repo [nama-folder], pilih Public, lalu klik Create repository. Nama repo sebaiknya huruf kecil tanpa spasi (contoh: dashboard-kopi-nusa).

Berhasil kalau

Halaman repo barumu terbuka, alamatnya github.com/[username]/[nama-folder].

2.3Salin alamat repo

Langkah

Di halaman repo barumu klik tombol hijau Code, pastikan tab HTTPS aktif, lalu klik ikon salin. Alamatnya berbentuk:

https://github.com/[username]/[nama-folder]
Catatan

Simpan alamat ini. Kamu akan memakainya di langkah 5. Jangan pilih SSH kecuali kamu sudah punya SSH key.

3

Install Git dan konfigurasi identitas

Sekitar 15 menit

Git adalah program yang mencatat riwayat perubahan kode. Identitas (nama & email) dipakai untuk menandai setiap commit, supaya orang tahu siapa yang mengubah apa.

3.1Install Git

Windows

Buka git-scm.com/install/windows, unduh pemasang 64-bit, lalu jalankan. Pertahankan pilihan bawaan, termasuk Git Credential Manager (penting untuk login).

Mac

Buka git-scm.com/install/mac dan ikuti petunjuk di halaman itu.

Verifikasi

Buka PowerShell (Windows) atau Terminal (Mac), jalankan:

git --version

Harus muncul nomor versi (contoh: git version 2.47.0).

3.2Set nama dan email

Perintah

Jalankan dua perintah ini, ganti dengan nama dan emailmu. Gunakan email yang sama dengan akun GitHub.

git config --global user.name "Nama Kamu"
git config --global user.email "emailmu@example.com"
Tips

Kalau tidak mau email asli tampil publik, pakai email noreply GitHub: username@users.noreply.github.com (lihat Settings → Emails di GitHub).

3.3Verifikasi konfigurasi

git config --global user.name
git config --global user.email
git config --global --get credential.helper
Berhasil kalau

Nama dan emailmu tampil, dan credential.helper menampilkan manager (Git Credential Manager). Kalau kosong, lihat bagian Troubleshooting.

4

Autentikasi GitHub (OpenCode / Freebuff)

Sekitar 20 menit

Supaya kamu bisa push (unggah kode) ke GitHub, komputermu harus "dikenali" oleh GitHub. Kita pakai Git Credential Manager (GCM) yang sudah terpasang bersama Git. Ia menyimpan loginmu sekali, lalu dipakai otomatis.

Awam? Pilih Opsi A (Device flow)

Tidak perlu buat token manual. Cukup satu perintah, lalu buka browser dan masukkan kode. Paling mudah dan aman.

4.1Cek Git Credential Manager

git credential-manager --version
Berhasil kalau

Muncul nomor versi (contoh: 2.9.0). Kalau "not recognized", Git belum terpasang dengan benar (ulangi langkah 3.1).

4.2Opsi A — Device flow (disarankan)

Perintah

Jalankan di PowerShell/Terminal:

git credential-manager github login --device
Yang terjadi

Terminal menampilkan kode (mis. ABCD-1234) dan alamat https://github.com/login/device. Buka alamat itu di browser, masuk ke akun GitHubmu, masukkan kode. Setelah "Authorized", terminal selesai dengan sendirinya.

Kalau --device tidak jalan

Coba tambahkan --no-ui: git credential-manager github login --device --no-ui.

Berhasil kalau

Perintah selesai tanpa error, dan git credential-manager github list menampilkan username GitHubmu.

4.3Cek akun tersimpan

git credential-manager github list
Berhasil kalau

Daftar akun tersimpan muncul. Dengan Opsi A, itu nama akunmu (mis. muhian). Untuk memakai akun lain, logout lalu login lagi.

4.4Ganti akun / logout

git credential-manager github logout <username>
Catatan

Logout membuang credential akun itu dari komputer ini. Setelah logout, akun tidak bisa dipakai sampai login lagi.

5

Buka repo dan minta AI siap pakai Git

Sekitar 10 menit

Dengan Git + credential helper terautentikasi (bab 4), OpenCode/Freebuff bisa mengurus git untukmu. Kamu tidak perlu ketik perintah git yang membingungkan, cukup beri AI satu prompt.

5.1Beri AI daftar isi repo

Prompt
Buka repo https://github.com/muhian/tesekraf/tree/parfumku_web, lalu buat branch baru di dalamnya.
Berhasil kalau

AI selesai memproses repo, dan di browser kamu bisa melihat branch baru di repo GitHub kamu.

5.2Minta AI commit & push

Prompt
[Tulis atau minta AI menyiapkan perubahan, lalu] commit dan push ke branch tersebut.
Catatan

AI memakai Git Credential Manager yang tersimpan di komputer kamu (dari bab 4), jadi tidak perlu password manual. Karena itu, tahap manual git add/commit/push tidak wajib peserta.

5.3Cek hasil di GitHub

Berhasil kalau

Branch baru muncul di tab Branches repo, dan file/perubahan tercatat di commit tersebut.

6

Troubleshooting GitHub

6.1Gejala umum dan solusi

ErrorKegiatan
Repository not foundRepo salah, atau akun GitHub yang dipakai belum dibuat. Cek nama repo (huruf kecil, tanpa spasi) dan username.
Invalid username or tokenToken kadang kadaluarsa atau salah akun. Logout: git credential-manager github logout <username>, lalu login lagi.
Authentication failedBelum login, atau token tidak punya scope repo. Buat token baru dengan scope repo, lalu login via Opsi B.
Permission deniedRepo private dan kamu bukan anggota/team. Pakai akun yang punya akses, atau ubah repo ke Public.
remote: Repository not foundAlias push ke repo yang tidak kamu miliki. Pastikan git remote -v benar.
Kalau tidak ada di daftar

Jalankan git credential-manager github list untuk melihat akun apa yang sedang tersimpan di komputer ini.

7

Deploy ke Vercel

Sekitar 20 menit

Panduan deploy dari repo GitHub ke Vercel untuk aplikasi Web UMKM ini.

7.1Deploy dari repo GitHub

Langkah

Buka vercel.com/new, klik Import GitHub, pilih repo muhian/tesekraf, lalu klik Deploy.

Catatan

Pastikan branch main sudah ada dan berisi kode aplikasi sesuai panduan.

7.2Isi environment variable

Langkah

Sebelum deploy, buka Settings → Environment Variables di Vercel, lalu tambahkan:

BETTER_AUTH_URL=https://[nama-folder].vercel.app
BETTER_AUTH_SECRET=[kunci baru dari bun x @better-auth/cli secret]
Catatan

Jangan pakai kunci yang sama dengan .env.local untuk produksi.

7.3Selesai dan dapat URL

Berhasil kalau

Deploy selesai, dan URL https://[nama-folder].vercel.app terbuka dan aplikasi jalan.

8

Kumpulkan link

Sekitar 5 menit

Tahap terakhir: kumpulkan link repository dan link produk yang sudah kamu kerjakan supaya bisa dicatat panitia.

8.1Buka formulir pengumpulan

Langkah

Buka formulir pengumpulan, lalu isi data diri dan kedua link di bawah.

8.2Isi link repository

Isi

Alamat repo GitHub kamu, contoh: https://github.com/[username]/[nama-folder]

8.3Isi link produk

Isi

URL hasil deploy dari Vercel, contoh: https://[nama-folder].vercel.app

8.4Kirim

Berhasil kalau

Formulir terkirim dan muncul halaman konfirmasi bahwa jawabanmu sudah tercatat.
