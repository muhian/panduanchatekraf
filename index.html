Pilih alat AI kamu

Alat AI adalah aplikasi yang menulis dan membetulkan kode atas perintahmu. Pilih satu, petunjuk di panduan ini ikut berubah. Tombol yang sama ada di kanan bawah.

Freebuff Desktop gratis, tanpa API key dan tanpa kartu kredit. Biayanya ditutup iklan teks.

OpenCode Desktop bersifat open source dan menyediakan model gratis bawaan. Model gratis bisa dibatasi atau berganti sewaktu-waktu.

Komputermu terdeteksi otomatis. Kalau salah, ganti Windows atau Mac di kanan bawah.

0.1Buat akun GitHub dan Vercel

GitHub

Daftar di github.com/signup, lalu verifikasi emailmu.

Vercel

Buka vercel.com/signup dan pilih Continue with GitHub.

Berhasil kalau

Kamu bisa membuka GitHub dalam keadaan login, dan dashboard Vercel terbuka.

0.2Pasang Git

Windows

Buka git-scm.com/install/windows, unduh pemasang 64-bit, lalu jalankan. Pertahankan pilihan bawaan, termasuk Git Credential Manager.

Mac

Buka git-scm.com/install/mac dan ikuti petunjuk di halaman itu.

Berhasil kalau

git --version menampilkan nomor versi. Login GitHub tidak diminta sekarang; jendela login muncul sendiri saat push pertama.

0.3Pasang editor dan alat AI

Editor

Pasang Visual Studio Code. Kamu akan sering melihat file yang diubah AI di sini.

Alat AI

Buka freebuff.com/desktop, unduh versi untuk komputermu, lalu pasang.

Alat AI

Buka opencode.ai/download, unduh aplikasi desktop, lalu pasang.

Berhasil kalau

Aplikasi alat AI terbuka dan menampilkan layar awal.

Kalau gagal

Peringatan keamanan saat membuka aplikasi? Lihat bagian Troubleshooting. Kalau tetap tidak jalan, ganti alat AI lewat tombol kanan bawah.

1

Aturan dan pengaman

Kamu merawat aplikasi orang lain: memperbaiki tampilan, membetulkan bug, dan menutup celah keamanan. Perananmu adalah pengambil keputusan dan pemeriksa, AI yang mengetik kodenya.

Commit kecil, sering

Satu perbaikan, satu commit. Kalau AI merusak sesuatu, kamu bisa kembali ke versi terakhir yang jalan.

Rahasia tidak masuk repo

.env.local berisi kunci sesi. File itu tidak boleh ikut ter-commit, dan repo publik berarti siapa pun bisa membacanya.

Klien tidak dipercaya

Validasi dan izin harus ada lagi di server. Memeriksa di browser saja bukan keamanan, hanya kenyamanan.

Satu tugas, satu prompt

Jangan minta AI mengerjakan revamp, fix, dan security sekaligus. Periksa hasil tiap langkah sebelum lanjut.

2

Buat akun GitHub dan repo baru

Sekitar 15 menit

Repo adalah "folder proyek di internet". Semua kode, riwayat perubahan, dan kolaborasi terjadi di sana. Kamu butuh satu repo milikmu sendiri untuk mengerjakan tugas.

2.1Buat akun GitHub

Langkah

Buka github.com/signup. Isi email, password, dan username. Username akan jadi bagian alamat profilmu: github.com/[username].

Verifikasi

Cek email, masukkan kode verifikasi yang dikirim GitHub. Tanpa verifikasi, kamu tidak bisa membuat repo.

Berhasil kalau

Kamu bisa login ke github.com dan melihat dashboard awal (halaman dengan daftar repo).

2.2Buat repo baru

Isi form

Nama repo [nama-folder], pilih Public, lalu klik Create repository. Nama repo sebaiknya huruf kecil tanpa spasi (contoh: dashboard-kopi-nusa).

Berhasil kalau

Halaman repo barumu terbuka, alamatnya github.com/[username]/[nama-folder].

2.3Salin alamat repo

Langkah

Di halaman repo barumu klik tombol hijau Code, pastikan tab HTTPS aktif, lalu klik ikon salin. Alamatnya berbentuk:

https://github.com/[username]/[nama-folder]
Catatan

Simpan alamat ini. Kamu akan memakainya di langkah 5. Jangan pilih SSH kecuali kamu sudah punya SSH key.

3

Install Git dan konfigurasi identitas

Sekitar 15 menit

Git adalah program yang mencatat riwayat perubahan kode. Identitas (nama & email) dipakai untuk menandai setiap commit, supaya orang tahu siapa yang mengubah apa.

3.1Install Git

Windows

Buka git-scm.com/install/windows, unduh pemasang 64-bit, lalu jalankan. Pertahankan pilihan bawaan, termasuk Git Credential Manager (penting untuk login).

Mac

Buka git-scm.com/install/mac dan ikuti petunjuk di halaman itu.

Verifikasi

Buka PowerShell (Windows) atau Terminal (Mac), jalankan:

git --version

Harus muncul nomor versi (contoh: git version 2.47.0).

3.2Set nama dan email

Perintah

Jalankan dua perintah ini, ganti dengan nama dan emailmu. Gunakan email yang sama dengan akun GitHub.

git config --global user.name "Nama Kamu"
git config --global user.email "emailmu@example.com"
Tips

Kalau tidak mau email asli tampil publik, pakai email noreply GitHub: username@users.noreply.github.com (lihat Settings → Emails di GitHub).

3.3Verifikasi konfigurasi

git config --global user.name
git config --global user.email
git config --global --get credential.helper
Berhasil kalau

Nama dan emailmu tampil, dan credential.helper menampilkan manager (Git Credential Manager). Kalau kosong, lihat bagian Troubleshooting.

4

Autentikasi GitHub (OpenCode / Freebuff)

Sekitar 20 menit

Supaya kamu bisa push (unggah kode) ke GitHub, komputermu harus "dikenali" oleh GitHub. Kita pakai Git Credential Manager (GCM) yang sudah terpasang bersama Git. Ia menyimpan loginmu sekali, lalu dipakai otomatis.

Awam? Pakai Device flow

Tidak perlu buat token manual. Cukup satu perintah, lalu buka browser dan masukkan kode. Paling mudah dan aman.

4.1Cek Git Credential Manager

git credential-manager --version
Berhasil kalau

Muncul nomor versi (contoh: 2.9.0). Kalau "not recognized", Git belum terpasang dengan benar (ulangi langkah 3.1).

4.2Device flow (disarankan)

Perintah

Jalankan di PowerShell/Terminal:

git credential-manager github login --device
Yang terjadi

Terminal menampilkan kode (mis. ABCD-1234) dan alamat https://github.com/login/device. Buka alamat itu di browser, masuk ke akun GitHubmu, masukkan kode. Setelah "Authorized", terminal selesai dengan sendirinya.

Kalau --device tidak jalan

Coba tambahkan --no-ui: git credential-manager github login --device --no-ui.

Berhasil kalau

Perintah selesai tanpa error, dan git credential-manager github list menampilkan username GitHubmu.

4.3Cek akun tersimpan

git credential-manager github list
Berhasil kalau

Daftar akun tersimpan muncul. Dengan device flow, itu nama akunmu (mis. muhian). Kalau akun tidak muncul, ulangi langkah 4.2.

5

Tahap prompting: bangun web dengan AI

Sekitar 90 menit

Inilah bagian intinya: kamu memberi instruksi, AI yang menulis kode. Polanya selalu sama — minta rencana dulu, satu prompt satu tujuan, lalu baca perubahan sebelum disetujui.

Tiga kebiasaan yang bikin aman

1) Minta AI menulis dokumen rencana sebelum menulis kode. 2) Satu prompt untuk satu fitur, jangan digabung. 3) Setelah tiap iterasi, minta AI menunjukkan git diff dan menjelaskan perubahannya sebelum commit.

5.1Siapkan repo di laptop

Prompt
Buka repo https://github.com/[username]/[nama-folder], lalu buat branch baru di dalamnya.
Berhasil kalau

Folder proyek ada di laptopmu, dan branch baru terlihat di halaman repo GitHub.

5.2Minta AI menulis spesifikasi (SPEC.md)

Prompt
Bertindaklah sebagai System Analyst dan Software Engineer. Buat SPEC.md untuk aplikasi "[nama brand]", katalog dan dashboard produk UMKM berbasis web untuk latihan 1 hari.
Pengguna: calon pembeli dan pengelola toko pada satu perangkat.
Fitur MVP: katalog 8 produk contoh, nama, kategori, harga Rupiah, stok, unggulan, pencarian, filter kategori, sorting, tombol pesan WhatsApp, dashboard demo CRUD, ringkasan total produk/stok/kategori, dan penyimpanan localStorage.
Model produk: id, nama, kategori, harga (angka >= 0), stok (integer >= 0), deskripsi, imageUrl, unggulan.
Batasan: jangan menyimpan API key, jangan menjalankan perintah berbahaya, data contoh nonpribadi, dan jangan memakai aset berhak cipta.
Kriteria penerimaan harus dapat diperiksa secara manual.
Output: tujuan, pengguna, daftar fitur, data model, risiko, out-of-scope, acceptance criteria, dan rencana implementasi per iterasi.
Jangan menulis kode aplikasi dulu.
Berhasil kalau

File SPEC.md muncul dan belum ada kode aplikasi yang ditulis.

5.3Rancang tampilan (UI-SPEC.md)

Prompt
Berdasarkan SPEC.md, buat UI-SPEC.md: warna hangat khas UMKM, font sans-serif yang mudah dibaca, kontras aksesibel, layout mobile-first, navbar sticky, hero, grid produk responsif, kontrol pencarian/filter/sorting, tombol WhatsApp, empty state, dan dashboard demo. Buat wireframe teks untuk desktop dan mobile. Jangan menulis kode dulu.
Berhasil kalau

UI-SPEC.md berisi warna, font, tata letak tiap halaman, dan wireframe teks.

5.4Susun rencana iterasi (TASKS.md)

Prompt
Baca SPEC.md dan UI-SPEC.md. Buat TASKS.md dengan milestone: (1) kerangka proyek, (2) landing dan 8 produk, (3) pencarian/filter/sorting, (4) integrasi WhatsApp, (5) dashboard CRUD, (6) localStorage dan import/export JSON, (7) unit test, (8) security review, (9) deployment. Setiap milestone memuat acceptance criteria, file yang disentuh, dan perintah uji. Jangan menulis kode dulu.
Berhasil kalau

TASKS.md berisi daftar milestone yang bisa dicentang satu per satu.

5.5Minta AI membuat kerangka proyek

Prompt
Baca SPEC.md, UI-SPEC.md dan TASKS.md. Siapkan proyek Vite + JavaScript vanilla pada folder saat ini, tanpa subfolder tambahan. Pisahkan menjadi src/main.js, src/products.js, src/store.js, src/ui.js, src/style.css. Tambahkan .gitignore untuk node_modules, dist, .env, dan vite.config.js dengan base './'. Jangan menginstal paket tambahan selain yang dibutuhkan. Setelah selesai, jalankan npm install lalu npm run dev, dan beri tahu alamat localhost-nya.
Berhasil kalau

package.json, index.html, folder src/, .gitignore, dan vite.config.js ada, lalu alamat localhost terbuka di browser.

5.6Bangun katalog dan 8 produk

Prompt
Baca SPEC.md dan UI-SPEC.md. Buat landing page dengan header sticky, hero, CTA ke katalog, 8 produk contoh (fiktif) di src/products.js, 4 kategori, harga Rupiah, stok, badge unggulan, dan kartu produk responsif. Gunakan placeholder emoji, bukan aset berhak cipta. Hanya ubah file UI dan data yang relevan.
Berhasil kalau

8 produk dan hero tampil rapi di desktop maupun layar ponsel.

5.7Tambah pencarian, filter, dan sorting

Prompt
Tambahkan pencarian produk case-insensitive pada nama dan deskripsi, filter kategori, serta sorting harga termurah/termahal dan nama A-Z. Semua filter dapat bekerja bersama. Jika hasil kosong, tampilkan empty state. Pisahkan fungsi murni filterProducts(products, { query, kategori, sort }) di src/store.js agar mudah diuji.
Berhasil kalau

Pencarian dan filter kombinasi bekerja, dan empty state muncul saat hasil kosong.

5.8Tambah tombol pesan WhatsApp

Prompt
Tambahkan tombol "Pesan via WhatsApp" pada setiap kartu. Buat fungsi buildWhatsAppUrl(nomor, produk) di src/store.js yang memvalidasi nomor tujuan dalam format internasional dan memakai encodeURIComponent untuk pesan. Nomor pemilik disimpan sebagai konstanta WHATSAPP_NUMBER di src/products.js. Bila stok nol, nonaktifkan tombol pemesanan. Jangan menambahkan payment gateway.
Berhasil kalau

Tombol membuka tautan wa.me dengan pesan yang sudah ter-encode, dan produk stok 0 tidak bisa dipesan.

5.9Buat dashboard pengelolaan produk

Prompt
Buat halaman dashboard demo yang menampilkan total produk, total stok, kategori aktif, tabel produk, dan form tambah/edit/hapus. Validasi nama wajib, harga angka >= 0, stok integer >= 0, kategori valid. Konfirmasi sebelum menghapus. Pastikan perubahan langsung tampak di katalog publik. Belum menambahkan login, password, atau sesi.
Berhasil kalau

Tambah, edit, dan hapus produk mengubah daftar sekaligus kartu statistik.

5.10Buat halaman admin dan landing page

Prompt
Buat dua halaman untuk proyek ini.
Halaman admin: login dan pengelolaan produk dengan gambar.
Landing page: tampilkan bagian hero dan bagian produk.
Stack: fullstack tanpa database (semua data disimpan di browser untuk tujuan edukasi).
Target: deploy ke Vercel.
Berhasil kalau

Halaman admin terbuka, login berfungsi, produk bisa ditambah/diubah/dihapus beserta gambarnya, dan landing page menampilkan hero serta daftar produk.

Dashboard lokal bukan sistem login

loginData hanya tersimpan di satu browser dan bisa diubah penggunanya. Jangan menyebut dashboard ini aman untuk banyak pengguna. Untuk produksi butuh backend, autentikasi, dan database.

5.11Simpan data dengan localStorage

Prompt
Simpan array produk ke localStorage dengan key "produk:v1". Saat dimuat, lakukan JSON.parse dalam try/catch dan validasi struktur serta tipe tiap field (nama string, kategori valid, harga >= 0, stok integer >= 0). Jika data rusak, tampilkan pemberitahuan dan pulihkan data contoh. Tambahkan export JSON, import JSON tervalidasi, dan reset demo. Jangan menghapus data lama bila impor gagal.
Berhasil kalau

Produk tetap ada setelah halaman di-refresh, dan file impor yang tidak valid ditolak.

5.12Uji dan audit keamanan

Prompt uji
Tambahkan Vitest dan minimal 20 unit test untuk filterProducts, validateProduct, buildWhatsAppUrl, parseProductsJSON, dan formatRupiah. Sertakan kasus batas harga/stok, kategori tidak valid, payload rusak, nomor telepon, serta kombinasi query+kategori+sorting. Jalankan npm test lalu laporkan hasil aktual. Jangan mengarang test yang tidak dijalankan.
Prompt audit
Audit proyek dengan fokus OWASP Top 10 untuk aplikasi statis: XSS, penggunaan innerHTML (pastikan semua data pengguna di-escape), penanganan URL, validasi impor JSON, dependency supply chain, kebocoran secret, dan konfigurasi publik. Bedakan temuan yang terbukti dari dugaan. Laporkan file/baris, tingkat risiko, dan rekomendasi.
Berhasil kalau

Hasil npm test ditampilkan apa adanya, dan laporan audit menyebut file serta tingkat risiko.

5.13Commit dan push lewat AI

Prompt
Tampilkan git diff, jelaskan perubahannya, lalu commit dan push ke branch yang tadi kamu buat. Tulis pesan commit yang jelas dan ringkas.
Berhasil kalau

Branch di GitHub berisi commit terbaru, dan file proyek terlihat di sana.

Catatan

AI memakai Git Credential Manager dari bab 4, jadi tidak perlu ketik password atau perintah git manual.

6

Troubleshooting GitHub

6.1Gejala umum dan solusi

ErrorKegiatan
Repository not foundRepo salah, atau akun GitHub yang dipakai belum dibuat. Cek nama repo (huruf kecil, tanpa spasi) dan username.
Invalid username or tokenToken kadang kadaluarsa atau salah akun. Logout: git credential-manager github logout <username>, lalu login lagi.
Authentication failedBelum login, atau login tersimpan untuk akun lain. Jalankan login device flow (langkah 4.2), lalu coba push lagi.
Permission deniedRepo private dan kamu bukan anggota/team. Pakai akun yang punya akses, atau ubah repo ke Public.
remote: Repository not foundAlias push ke repo yang tidak kamu miliki. Pastikan git remote -v benar.
Kalau tidak ada di daftar

Jalankan git credential-manager github list untuk melihat akun apa yang sedang tersimpan di komputer ini.

7

Deploy ke Vercel

Sekitar 20 menit

Panduan deploy dari repo GitHub ke Vercel. Kalau proyekmu memakai Vite, Vercel mengisikan build command sendiri; kalau masih HTML statis, cukup import lalu deploy.

7.1Deploy dari repo GitHub

Langkah

Buka vercel.com/new, klik Import GitHub, pilih repo muhian/tesekraf, lalu klik Deploy.

Catatan

Pastikan branch yang mau dideploy sudah di-push ke GitHub. Kalau proyek memakai Vite, biarkan Framework Preset Vite dengan Build Command npm run build dan Output Directory dist.

7.2Selesai dan dapat URL

Berhasil kalau

Deploy selesai, dan URL https://[nama-folder].vercel.app terbuka dan web tampil normal.

Catatan

Tidak perlu environment variable atau kunci rahasia. Kalau build gagal, cek log deploy dan pastikan npm run build berhasil di laptop. Contoh hasil deploy: tesekraf.vercel.app.
